The website security baseline

Most small websites aren't hacked by geniuses. They're hacked through a reused password, an old plugin or an account nobody remembered. These ten controls close the doors attackers use most.

By Web.Life EditorialUpdated 26 November 20264 min read

Think in terms of accounts, not just the site

Your website is only as secure as every account that can change it: the domain registrar, the DNS provider, the host, the CMS, the email account that receives password resets, and any developer or plugin with access. An attacker who controls your registrar or your email can take the whole site without touching its code. So the baseline starts with accounts.

The ten controls

  1. Two-factor authentication everywhere it's offered. Start with your email, registrar, host and CMS admin. Prefer an authenticator app or a hardware security key over SMS codes where you can.
  2. A password manager and unique passwords. Every account gets its own long, random password from the password generator. Reuse is how one breached service becomes ten compromised accounts.
  3. Registrar lock and auto-renew. Transfer lock prevents unauthorised domain transfers; auto-renew with a valid card prevents accidental expiry.
  4. A recovery email that isn't on the domain. If the domain lapses or is hijacked, you'll still be able to receive recovery messages.
  5. Least privilege. Give each person the lowest access they need, remove accounts when people leave, and never share one admin login.
  6. Updates on a schedule. Core software, themes and plugins should be updated promptly, especially security releases. Delete plugins and themes you don't use; inactive code can still be vulnerable.
  7. Automatic, off-site backups. Daily for active sites, stored somewhere other than your host, with a restore tested at least quarterly. See backups and incident response.
  8. HTTPS everywhere. A valid certificate on every page, renewed automatically, with HTTP redirecting to HTTPS.
  9. Monitoring. An uptime monitor, alerts for new admin users or file changes where your platform supports them, and attention to unusual traffic spikes.
  10. Know your exposure. Check whether your email addresses appear in public breaches at Have I Been Pwned and change any affected passwords. Our Web Pulse lists the newest breaches.

Recognising phishing aimed at site owners

Owners receive convincing fake messages: "your domain expires today", "your hosting payment failed", "we detected copyright infringement, see attached". The defence is a habit: never log in from a link in an email. Open your registrar or host by typing its address or using a bookmark, and check for the alert there. Be especially suspicious of urgency, unexpected attachments and requests to "verify" credentials.

If you use a CMS

  • Change the default admin username and limit login attempts.
  • Install plugins only from reputable sources with recent updates and many active users.
  • Consider a web application firewall from your host or a CDN.
  • Keep PHP or the server runtime on a supported version; your host's control panel usually lets you switch.

If you use a static site

There's no login on the site itself to attack, which removes most risk. Your exposure moves to the accounts that publish it: your code repository and hosting. Protect those with two-factor authentication, restrict who can push to the main branch, and review any automated workflows that can modify the site.

A 30-minute start

  1. Turn on two-factor authentication for your email and registrar right now.
  2. Check that auto-renew and registrar lock are on.
  3. Confirm when your last backup ran, and where it's stored.
  4. List everyone who has admin access and remove anyone who shouldn't.
