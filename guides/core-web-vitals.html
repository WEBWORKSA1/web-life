Core Web Vitals in plain English

Core Web Vitals are three measurements of how a page feels to real visitors: how fast the main content appears, how quickly it responds, and whether it jumps around. Here's what each means and how to fix it.

By Web.Life EditorialUpdated 26 November 20264 min read

The three metrics

MetricWhat it measuresGoodPoor
LCP, Largest Contentful PaintHow long until the biggest piece of content (usually a hero image or headline) is visible2.5 s or lessover 4 s
INP, Interaction to Next PaintHow quickly the page visibly responds after a tap, click or key press200 ms or lessover 500 ms
CLS, Cumulative Layout ShiftHow much content unexpectedly moves while the page is in use0.1 or lessover 0.25

INP replaced an older metric, First Input Delay, in March 2024. Google assesses each metric at the 75th percentile of real page loads, so a page "passes" when at least three out of four visits meet the good threshold.

Field data versus lab data

Field data comes from real Chrome users visiting your site and is what search uses. You'll see it in Search Console's Core Web Vitals report and at the top of PageSpeed Insights when your site has enough traffic. Lab data comes from a simulated test on one device and connection. It's perfect for debugging but can differ from what visitors experience. Fix with lab tools, confirm with field data a few weeks later.

Fixing LCP

LCP is usually an image, so start there.

  1. Find the LCP element in PageSpeed Insights or your browser's performance panel.
  2. Make it smaller: modern formats (WebP or AVIF), dimensions that match how big it displays, and sensible compression.
  3. Make it discoverable early: don't lazy-load the hero image, and consider fetchpriority="high" on it.
  4. Reduce what blocks rendering: heavy CSS, render-blocking scripts and slow web fonts.
  5. Speed up the server: caching, a content delivery network and quality hosting reduce the wait before anything arrives.

Fixing INP

Poor INP almost always means too much JavaScript running on the main thread.

  • Remove scripts and third-party widgets you don't need. Each chat bubble, tracker and social embed costs responsiveness.
  • Break long tasks into smaller pieces so the browser can respond between them.
  • Defer non-essential work until after the page is interactive.
  • Give immediate visual feedback on clicks, even if the full result takes longer.

Fixing CLS

  • Always set width and height (or an aspect ratio) on images, videos and embeds so space is reserved.
  • Reserve space for ads and late-loading banners. Ad slots that push content down are a classic cause.
  • Don't insert content above what someone is reading unless they asked for it.
  • Load web fonts in a way that doesn't reflow text dramatically when they arrive.

Do Core Web Vitals affect rankings?

They're part of the page experience signals search engines use, but relevance and content quality matter far more. A fast page with weak content won't outrank a slower, much better answer. Treat the vitals as a tie-breaker in search and a direct driver of conversions: faster, steadier pages keep more visitors, which means more readers, leads and ad views.

A one-hour speed session

  1. Test your homepage and your highest-traffic page in PageSpeed Insights on mobile.
  2. Fix the LCP image on both.
  3. Remove one third-party script you can live without.
  4. Add dimensions to any images missing them.
  5. Estimate your page weight with the page-weight budget and set a limit for future pages.
